# 会议进度管理工具设计

## 1. 目标

构建一个面向单个项目管理者的桌面端 Web 工具。用户将钉钉群消息或会议记录原文粘贴进系统，由大模型生成结构化草稿，人工确认后形成可持续跟踪的项目、任务、进展、里程碑和风险数据，并按日期范围生成周报。

系统采用容器化部署，可先在本机运行，后续通过服务器已有的 Nginx 或 Caddy 绑定域名。首版不包含钉钉 API、消息通知、多人协作、附件管理和复杂甘特图。

## 2. 成功标准

- 管理员可以登录，未登录用户无法访问业务数据。
- 一段会议原文可以保存、调用大模型解析、人工校正并一次性确认入库。
- AI 不直接覆盖已有任务；疑似重复任务必须由用户决定更新或新建。
- 可以按项目、人员、状态和时间查看任务、进展、里程碑与风险。
- 可以选择日期范围生成可编辑、可复制的 Markdown 周报。
- Docker Compose 启动后数据写入持久化卷，容器重建或重启不丢失。
- 数据可导出为 JSON 和 CSV，便于迁移与备份。

## 3. 技术架构

- Python 3.12、Django、Django Templates。
- HTMX 提供解析、筛选和快速更新等局部交互；少量原生 JavaScript 只用于复制与必要的表单增强。
- Tailwind CSS 构建静态样式；生产镜像不运行 Node.js 服务。
- SQLite 数据库位于 `/data/app.sqlite3` 并启用 WAL；上传目录预留为 `/data/uploads`。
- Gunicorn 运行 Django 应用；`GET /health/` 提供容器健康检查。
- Docker Compose 仅运行一个应用服务并挂载命名卷。
- HTTPS、域名和反向代理由部署服务器现有 Nginx 或 Caddy 提供。
- pytest、pytest-django 用于自动化测试。

该架构针对单用户、低数据量场景优化。业务模型保持 Django ORM 可移植性；未来需要多人并发时，可将数据库切换到 PostgreSQL，而不改变业务层接口。

## 4. 身份认证与配置

系统只有一个管理员身份，使用 Django 内建用户、密码哈希、会话和 CSRF 防护。

首次启动时，入口脚本在不存在任何管理员的情况下读取 `ADMIN_USERNAME` 和 `ADMIN_PASSWORD` 创建管理员。已有管理员时不修改用户名或密码。管理员可以在登录后修改密码。

运行时配置：

- `DJANGO_SECRET_KEY`：生产环境必填。
- `DJANGO_DEBUG`：默认 `false`。
- `DJANGO_ALLOWED_HOSTS`：生产域名列表。
- `CSRF_TRUSTED_ORIGINS`：生产 HTTPS 来源列表。
- `ADMIN_USERNAME`、`ADMIN_PASSWORD`：首次启动创建管理员。
- `LLM_BASE_URL`、`LLM_API_KEY`、`LLM_MODEL`：OpenAI 兼容模型配置。
- `LLM_TIMEOUT_SECONDS`：模型请求超时，默认 60 秒。
- `DATA_DIR`：默认 `/data`。

日志不记录密码、API Key、完整请求头或会议原文。登录失败实施基于缓存和客户端地址的基础限速。

## 5. 数据模型

### Project

- `name`：唯一项目名称。
- `description`：项目说明。
- `status`：未开始、进行中、暂停、已完成、已归档。
- `progress`：0–100 的总体进度。
- `planned_start_date`、`planned_end_date`：计划日期，可为空。
- `created_at`、`updated_at`。

### Person

- `name`：唯一姓名。
- `note`：备注。
- `is_active`：是否仍用于新任务。

人员仅作为负责人字典，不对应登录账号。

### MeetingNote

- `title`、`meeting_date`、`raw_text`。
- `parse_status`：未解析、解析中、解析成功、解析失败、已入库。
- `parse_error`：对用户可见的精简错误。
- `raw_llm_response`：用于排查的模型原始响应，界面默认折叠。
- `created_at`、`updated_at`。

### ImportDraft

- `meeting_note`：所属会议记录。
- `payload`：通过服务端校验后的结构化 JSON 草稿。
- `created_at`、`confirmed_at`。

草稿与会议分离，以便失败后重新解析且不污染正式数据。每次重新解析生成新草稿，只有最后选择的草稿可以确认。

### Task

- `project`、`title`、`description`。
- `assignee`：可为空。
- `planned_start_date`、`due_date`、`acceptance_date`：可为空。
- `status`：未开始、进行中、待验收、已完成、已延期、阻塞。
- `priority`：低、普通、高、紧急。
- `progress`：0–100。
- `current_note`：当前状态说明。
- `source_meeting`：首次创建来源，可为空。
- `created_at`、`updated_at`、`completed_at`。

### ProgressUpdate

- `task`、`meeting_note`。
- `previous_progress`、`new_progress`。
- `previous_status`、`new_status`。
- `completed_work`：本次完成。
- `next_step`：下一步计划。
- `recorded_at`。

每次通过会议导入或任务页面更新任务时创建进展快照，从而保留周与周之间的变化。

### Risk

- `project`、`task`：任务可为空。
- `risk_type`：风险、阻塞、待决策、预警、异常。
- `content`。
- `owner`：可为空。
- `due_date`：可为空。
- `status`：待处理、跟进中、已解决、已关闭。
- `source_meeting`：可为空。
- `created_at`、`updated_at`、`resolved_at`。

### Milestone

- `project`、`name`、`description`。
- `target_date`：可为空。
- `status`：未开始、进行中、已完成、已延期。
- `source_meeting`：可为空。
- `created_at`、`updated_at`。

## 6. AI 解析

解析服务通过 OpenAI 兼容 Chat Completions 接口请求模型，并要求返回固定 JSON 对象。返回内容包含：

- 会议概要。
- 新任务候选。
- 现有任务更新候选。
- 进展记录。
- 风险与待决策事项。
- 里程碑。
- 无法确定、需要人工补充的字段和原因。

服务端在发送请求前提供当前活跃项目、人员及未完成任务的精简列表，帮助模型生成匹配建议。不会发送历史会议全文。

模型结果必须经过本地 Schema 校验和规范化：

- 日期转为 `YYYY-MM-DD`；缺少年份时使用会议日期年份。
- 进度必须是 0–100 的整数。
- 状态、优先级、风险类型必须映射到固定枚举。
- 未知项目或人员保留为待确认文本，不自动创建正式对象。
- 空标题、无意义任务和无法解析的日期标记为校验问题。

已有任务候选匹配使用项目、负责人、标准化标题进行评分。标准化只做空白、标点和常见前缀处理，不用模糊结果自动合并。确认页面显示候选任务、字段差异以及“更新现有任务 / 新建任务 / 忽略”选择。

AI 只产生草稿。正式入库必须由用户提交确认页面，且整个确认操作位于一个数据库事务中；任意条目校验失败时整批回滚。

## 7. 页面与交互

### 登录

居中登录表单。连续失败后显示剩余等待时间。登录后默认进入仪表盘。

### 仪表盘

- 进行中、待验收、已延期、阻塞任务统计。
- 项目进度列表。
- 本周到期和已经逾期的任务。
- 高优先级未解决风险。
- 最近会议记录。
- 显眼的“粘贴会议记录”入口。

### 快速记录

输入会议标题、会议日期和原始文本。保存原文后可触发 AI 解析。解析请求进行时显示状态，刷新或超时后仍可回到该会议记录重试。

### 解析确认

桌面双栏布局：左侧固定显示原文，右侧按任务、进展、风险、里程碑分组显示草稿。每条草稿都可以编辑、忽略和关联正式对象。确认前展示校验错误与疑似重复任务差异。

### 任务中心

默认表格视图，支持按项目、负责人、状态、优先级、截止日期筛选和排序。可在详情抽屉或页面修改状态、进度、日期和说明。提供按状态分列的简单看板视图。

### 项目详情

展示项目基本信息、里程碑时间线、任务状态分布、未解决风险、会议历史与最近进展。

### 人员视图

展示每位人员当前未完成任务、延期任务、待验收任务和历史完成记录。

### 周报

选择起止日期后，按照项目汇总：本期完成、当前进行、下一步计划、延期/阻塞、风险/待决策和里程碑变化。生成内容可以在文本框中编辑、复制为 Markdown，并可下载 Markdown 文件。生成周报不会修改业务数据。

### 设置与数据导出

显示模型配置是否完整，但不回显密钥。允许导出完整 JSON，以及项目、任务、进展、风险、里程碑的 CSV。提供修改管理员密码入口。

## 8. 异常与安全处理

- 模型超时、限流、网络失败或非法 JSON：保留会议原文和失败状态，显示可理解的错误及重试按钮。
- 同一会议重复确认：数据库约束与事务共同阻止重复写入。
- 并发提交：确认时锁定草稿并再次检查状态；已确认草稿只读。
- 无效筛选和表单数据：返回字段级错误，不产生部分更新。
- SQLite：设置合理 busy timeout，并保持单个 Gunicorn worker，避免单用户场景下不必要的写竞争。
- 数据文件不打入镜像；`/data` 只通过命名卷持久化。
- 生产环境关闭 Debug，设置安全 Cookie、代理 HTTPS 头、允许域名和可信来源。

## 9. 导出与备份

JSON 导出包含全部正式业务数据与会议原文，不包含用户密码、会话、API Key 和内部缓存。CSV 按实体分别导出为 ZIP 文件。

README 提供一致性备份方式：短暂停止应用后复制 Docker 命名卷中的 `app.sqlite3` 和 `uploads`。首版不内置计划任务或云端备份。

## 10. 测试与验收

自动化测试覆盖：

- 未登录访问保护、登录和修改密码。
- 首次管理员创建不覆盖已有密码。
- AI 响应 Schema 校验、枚举映射、日期归一化和错误呈现。
- 任务候选匹配只提示、不自动合并。
- 草稿确认创建或更新相应对象并生成进展历史。
- 草稿确认任一项失败时整批回滚，且不能重复确认。
- 任务筛选、逾期判断、项目统计和周报时间范围汇总。
- JSON/CSV 导出不包含秘密信息。
- 健康检查和关键安全配置。

容器验收：

- `docker compose build` 成功。
- `docker compose up` 后健康检查通过。
- 创建数据后重启容器，数据仍可读取。
- 浏览器完成登录、粘贴、解析预览、人工校正、确认入库、任务筛选和生成周报的完整流程。

## 11. 首版之外

以下功能不进入首版：钉钉 API 或机器人、自动通知、多人账号及权限、附件管理、复杂甘特图、移动端专项适配、后台任务队列、实时协作、自动云备份和飞书同步。后续只有在现有闭环稳定使用后再评估。
