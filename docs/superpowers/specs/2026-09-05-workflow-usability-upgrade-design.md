# 会议进度台体验升级设计

## 1. 范围

本次升级保持 Django Templates、原生 CSS/JavaScript、SQLite 和单用户部署不变，不新增外部服务或数据库表。改造现有闭环中的四个高频环节：会议入口、AI 草稿确认、任务进展更新和首页行动台。

## 2. 用户路径

1. 用户进入“会议”收件箱，粘贴钉钉群消息或会议记录。
2. 默认操作为保存后开始解析；也可仅保存原文。
3. 解析成功后，会议进入“待确认”。首页和会议列表提供继续入口。
4. 草稿页默认折叠可直接导入项，只展开缺项目、日期异常、人员未匹配或疑似重复的项目。
5. 用户确认导入后从任务详情记录“本次完成、下一步、风险、进度和状态”。
6. 首页、人员页与周报复用进展记录，减少重复录入。

## 3. 草稿确认

- 展示新增、更新、需确认、忽略的实时汇总。
- 项目未匹配时默认忽略，避免产生脏数据。
- 唯一且分数不低于 0.9 的候选任务，项目一致且负责人不冲突时推荐更新。
- 其他可明确映射项目的任务推荐新建。
- 每条任务用紧凑摘要行展示，详细字段放入原生 `details`。
- 需确认项默认展开；支持只看需确认、查看全部、批量接受推荐和批量忽略需确认项。
- 更新已有任务时展示已有任务与本次识别的关键字段差异。
- 风险和里程碑保持默认不入库，但匹配项目后可快速确认。
- 确认前按钮展示预计新增、更新和忽略数量。

## 4. 任务进展

- 新增任务详情页，基础属性和完整编辑是次级操作。
- 主要操作是一次进展更新，包含状态、进度、截止日期、当前说明、本次完成和下一步。
- 只填写文本也必须创建 `ProgressUpdate`，让周报能够归集。
- 状态变为已完成时设置 `completed_at`；重新打开时清空。
- 详情页显示倒序进展时间线和来源会议。

## 5. 首页与会议

- 首页从四个等权大数字改为可点击的行动摘要：待确认、逾期、本周到期、长期未更新、未解决风险。
- 逾期与未来七天到期互斥，完成任务不进入行动队列。
- 待确认仅展示每次会议最新且尚未确认的草稿。
- 增加会议列表，根据状态显示继续确认、重试解析、开始解析或查看结果。
- 会议录入页默认“保存并开始解析”，保留“仅保存”选项。
- 首页提供按负责人分组的跟进提示，可一键复制到钉钉。

## 6. 视觉与交互

- 使用浅色、低饱和暖灰和深绿色的 restrained 色彩策略。
- 固定字号层级，减少大标题、深色指标墙和重复悬浮卡片。
- 使用统一的 surface、data row、summary strip、chip、empty state 和 sticky action bar。
- 主要触控目标不小于 44px；状态变化通过 `aria-live` 反馈。
- 复制、筛选、批量处理都有即时反馈；支持 `/` 聚焦搜索、`n` 新建会议。
- 900px 以下改为单栏，620px 以下压缩导航与字段，不产生整页横向滚动。

## 7. 错误处理与性能

- 草稿展示一次加载未完成任务集合，避免每个草稿条目重复查询和遍历数据库。
- 三类草稿决策数量都在事务前验证，任何不完整提交整体回滚。
- 同步模型请求仍受 `LLM_TIMEOUT_SECONDS` 控制；本次优化等待反馈和恢复入口，但不伪装模型生成速度。
- 解析失败保留原文并在会议列表、详情页提供重试。

## 8. 验收

- 20 条以上草稿可以只浏览需确认项，并通过批量操作快速完成。
- 手工进展更新出现在任务时间线和本周周报。
- 待确认、逾期、近期到期的首页数字和列表一致。
- 会议在未解析、失败、待确认、已入库四种状态下都有明确下一步。
- 自动化测试、Django 检查、迁移检查、Docker 构建和实际浏览器桌面/窄屏检查全部通过。
