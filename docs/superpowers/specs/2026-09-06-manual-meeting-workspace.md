# 会议工作台（已确认设计）

单人主持、按项目和人员逐项询问进度。新增手动结构化入口，保留原有粘贴/AI 解析入口；不改变 Django、SQLite、原生前端和容器部署方式。

## 使用路径

1. 新建会议：主题、日期、开始时间、议题、关联项目、汇报人员。可提前安排未来会议。
2. 会中：左侧切换人员，右侧查看相关未完成任务；可以搜索其他任务及已完成任务。选择任务后记录状态、进度、本次完成、下一步、截止日、安排日期。未询问任务不产生变更，已询问不等于已完成。
3. 同一任务只保留一张本次记录卡；新增任务默认当前人员/项目，不把汇报人自动设成已有任务负责人。
4. 可以直接新增风险、待决策和普通纪要；缺少项目/人员时在当前页面快捷创建。
5. 所有会中内容自动暂存服务器，明显显示保存中、已保存、失败和版本冲突。可手动重试、暂存退出、刷新后恢复；失败时不得显示保存成功或直接离开。
6. 结束会议先核对，再明确确认。一次事务写入现有 Task、ProgressUpdate、Risk，重复确认不得重复入库。纯手动流程不调用大模型。
7. 自动生成可复制到钉钉的会议纪要。已确认会议只读。

## 数据与安全边界

- 独立的手动会议会话生命周期，不伪造 AI 解析成功状态。旧会议不重放、不改写。
- 草稿使用稳定 UUID；已有任务使用签名基线，确认前检查是否被其他操作更新。
- 过去日期会议的已有任务进度仅补记历史，不覆盖当前状态；新建任务、风险仍会明确列入确认预览。未来会议可以暂存但不能提前确认进度。
- 记录业务日期与实际录入时间分离，周报按业务日期纳入；保留项目/任务/人员快照供历史展示。
- 草稿只落 SQLite，现有备份/恢复可一并迁移；密钥仍通过原有 env 注入，不进入 Git、镜像或导出。
- 第一版不含混合 AI/手动自动合并、已确认会议撤销重开、复杂模板。

## 视觉与效率

沿用现有浅色中性/绿色风格。紧凑双栏工作区、明确当前汇报人和已记录数量，必要字段直接操作，补充字段渐进展开。桌面充分利用宽度，手机单栏无横向溢出。原生可访问控件、错误贴近操作、无外部字体/CDN/新前端框架。
